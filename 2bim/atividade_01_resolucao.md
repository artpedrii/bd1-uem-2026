# Atividade 1 — SQL com PostgreSQL/Supabase (Resolução)

Cenário: uma loja controla **categorias** e **produtos**.

---

## Exercício 1 — Criando CATEGORIA

```sql
CREATE TABLE categoria (
    id_categoria BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
);
```

---

## Exercício 2 — Conferindo a estrutura

No Table Editor, a tabela `categoria` mostra:

1. **Colunas criadas:** `id_categoria` e `nome`.
2. **Chave primária:** `id_categoria`.
3. **Coluna com `NOT NULL`:** `nome`. A PK também é implicitamente `NOT NULL`.
4. **Geração automática:** `id_categoria` (`GENERATED BY DEFAULT AS IDENTITY`).

---

## Exercício 3 — Criando PRODUTO

```sql
CREATE TABLE produto (
    id_produto   BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome         VARCHAR(100)  NOT NULL,
    preco        NUMERIC(10,2) NOT NULL CHECK (preco >= 0),
    estoque      INTEGER       NOT NULL DEFAULT 0 CHECK (estoque >= 0),
    id_categoria BIGINT        NOT NULL,
    FOREIGN KEY (id_categoria) REFERENCES categoria (id_categoria)
);
```

## Exercício 15 — Testando NOT NULL

> **O PostgreSQL deverá aceitar o registro? Por quê?**

**Não.** `nome` é `NOT NULL`, ou seja, obrigatório, e não tem `DEFAULT`.

```sql
INSERT INTO produto (preco, estoque, id_categoria)
VALUES (100.00, 3, 1);
```

Resultado:

```text
ERROR: null value in column "nome" of relation "produto" violates not-null constraint
```

Restrição responsável: **`NOT NULL`** na coluna `nome`.

---

## Exercício 16 — Testando CHECK

```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Monitor', -500.00, 10, 1);
```

1. **Não**, o registro não foi inserido.
2. Restrição envolvida: **`CHECK (preco >= 0)`**. O erro é do tipo `violates check constraint "produto_preco_check"`.
3. Regra violada: o preço não pode ser negativo.

---

## Exercício 17 — Testando a chave estrangeira

> **O banco deveria permitir essa inserção? Por quê?**

**Não.** A categoria 9999 não existe, e um produto não pode referenciar uma categoria inexistente.

```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Produto teste', 50.00, 1, 9999);
```

```text
ERROR: insert or update on table "produto" violates foreign key constraint "produto_id_categoria_fkey"
```

**Integridade referencial:** todo valor de uma chave estrangeira deve existir como chave primária na tabela referenciada (ou ser `NULL`, o que aqui é proibido por `NOT NULL`). Isso evita "produtos órfãos".

## Exercício 18 — Identifique os problemas

### A
1. **Problema:** preço negativo (`-150.00`).
2. **Restrição violada:** `CHECK (preco >= 0)`.
3. **Correção:**
```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Teclado', 150.00, 10, 1);
```

### B
1. **Problema:** `nome` não foi informado.
2. **Restrição violada:** `NOT NULL` em `nome`.
3. **Correção:**
```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Hub USB', 250.00, 5, 1);
```

### C
1. **Problema:** estoque negativo (`-2`).
2. **Restrição violada:** `CHECK (estoque >= 0)`.
3. **Correção:**
```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Webcam', 300.00, 2, 1);
```

### D
1. **Problema:** `id_categoria = 9999` não existe.
2. **Restrição violada:** `FOREIGN KEY` (integridade referencial).
3. **Correção** (usando Acessórios, id 3):
```sql
INSERT INTO produto (nome, preco, estoque, id_categoria)
VALUES ('Headset', 450.00, 5, 3);
```

> **Observação:** inserções que falham também consomem valores da sequência `IDENTITY`. Por isso os `id_produto` podem ter "buracos" (ex.: 1, 2, 3, 4, 5, 6, 10, 11...). Isso é normal.

## Exercício 20 — Um novo problema

Com 500 produtos, `SELECT *` traz tudo. Para filtrar, é necessário adicionar uma **condição**, com a cláusula `WHERE`:

```sql
-- preço > 500
SELECT * FROM produto WHERE preco > 500;

-- categoria Informática (id 1)
SELECT * FROM produto WHERE id_categoria = 1;

-- produto chamado Notebook
SELECT * FROM produto WHERE nome = 'Notebook';
```
